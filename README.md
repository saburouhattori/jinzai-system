# 人材管理システム (Jinzai System)

## 概要 (Overview)

Google Apps Script (GAS) と Google スプレッドシートを活用した人材紹介事業（Smile Dream Co.,Ltd.）向けの管理システムです[cite: 5]。
候補者（登録者）の管理、求人案件の管理、面接から採用（内定）、在留資格（COE）申請情報の管理・外部連携までのプロセスを一元管理し、業務の効率化を図ります[cite: 5]。日本およびミャンマー拠点のスタッフが共同で運用することを想定して設計されています[cite: 5]。

## 主な機能 (Features)

* **候補者管理**:
  「登録者マスタ」への新規登録、更新、削除[cite: 5]。顔写真データを含んでいても高速に一括更新可能なロジックを実装[cite: 5]。新規登録時には「登録日」をシステム日付で自動入力し、名前・生年月日のリアルタイム重複チェック（同姓同名および同一生年月日の検知・確認ダイアログ）により二重登録を防止します[cite: 5]。また、呼び名のカッコ表記は自動で全角カッコ `（）` に統一され、名前変更時には関連する案件管理側の表記も自動置換されます[cite: 5]。

* **年齢自動計算**:
  スプレッドシートの DATEDIF 関数と ARRAYFORMULA を活用し、生年月日から満年齢をリアルタイムに自動計算[cite: 5]。メンテナンスフリーな運用を実現[cite: 5]。

* **案件・採用管理**:
  求人案件の登録、修正、削除機能[cite: 5]。および案件に対する候補者の面接結果（採用・不採用・辞退・取消）の登録・修正機能[cite: 5]。過去案件の結果修正時には、他案件で既に採用されている候補者や「辞退」「不採用」ステータスの候補者が誤ってリセットされないよう保護されます[cite: 5]。また、案件削除時には関連するマスタの面接履歴やステータスを自動でロールバックします[cite: 5]。

* **面接履歴と内定日の自動追記**:
  「面接結果の登録」実行時に、該当案件で面接を受けた全候補者（採用・不採用問わず）の「面接履歴」と結果を、「登録者マスタ」へ自動で改行追記します[cite: 5]。また、採用時は「内定日」も自動的にマスタへ反映されます[cite: 5]。

* **COE申請情報の登録・更新（日英バイリンガルUI・分野別連動制御）**:
  出入国在留管理庁の公式COE交付申請書様式に準拠した2段ラベル（日英併記UI）を採用[cite: 5]。検索時には対象候補者の「案件ID・採用事業者名・技能分野・内定日」および履歴書用の日本語学歴を参考情報として表示します[cite: 5]。また、採用案件の「技能分野（介護・外食業・飲食料品製造業）」に応じて対象外の技能試験項目を自動でグレーアウト（入力不可）し、技能実習経験・過去の交付申請歴・出入国歴・在日親族の有無（「無」選択時の詳細欄グレーアウト）や英語学歴・パスポート情報を一画面で正確に登録できます[cite: 5]。

* **入国・入職日の一括登録**:
  案件IDを指定して当該案件の採用者のみを自動抽出し、全員共通の日付セットまたは個別の微調整によって、「登録者マスタ」の入国日・入職日を一括で登録・更新する機能[cite: 5]。

* **自動リスト同期 (動的マッピング)**:
  登録者マスタの更新内容を「採用者一覧」「未採用者一覧」「簡易リスト」へ自動同期[cite: 5]。ヘッダー名（1行目の文字列）をキーにしてデータを自動振り分けするため、列の追加や移動にも柔軟に追従します[cite: 5]。また、「案件管理」シートの「面接結果詳細」および「内定日」を正本（SSoT）として、「登録者マスタ」「採用者一覧」「未採用者一覧」のステータス・採用事業者・内定日を一括反映します（「辞退」「不採用」ステータスは保護）[cite: 5]。

* **直感的なUI / 待機表示**:
  データの送受信や同期など、時間のかかる非同期処理中には画面全体を覆うローディングスピナーを表示し、システムの状態を視覚的にフィードバックします[cite: 5]。

* **ファイル・フォルダ自動連携機能（アップロード・スマートチップ化）**:
  * PCからのファイル直接アップロードに対応[cite: 5]。自動的に「案件ID_事業者名」のフォルダを作成・特定し、ドライブへ保存してスプレッドシートと連携します[cite: 5]。
  * 既存のGoogleドライブURL（ファイル・フォルダ）を入力・検索して追加することも可能[cite: 5]。URLがシートに登録されると、自動的に名前を取得しファイルは「📄」、フォルダは「📁」のアイコン付きでスマートチップ風に変換します[cite: 5]。

* **履歴書・簡易リスト生成**:
  候補者IDを指定して、提出用の履歴書や簡易リストを自動生成する機能[cite: 5]。

* **外部シート連携（Funtoco「支払い管理」および「COE info」連携）**:
  * **支払い管理連携**: 外部シート「海外ミャンマー管理リスト【Funtoco】」内の「支払い管理」シートへ、案件管理で確定した採用者情報をボタン一つで同期[cite: 5]。手動管理するステータス・金額・入金日・備考等のデータは保護しつつ、基本情報（内定日・入国日・入職日含む）を高速かつ安全に一括更新・自動クレンジングします[cite: 5]。
  * **COE info 連携**: 外部シート内の「COE info」スマートテーブル（全34列：日本語上／英語下）へ、内定登録時およびCOE申請情報保存時に採用者のCOE申請用データを自動転記（管理者メニューからの差分一括同期・更新行番号および変更項目の表示にも対応）[cite: 5]。最左列（A列「状況 / Status」）にて全必須項目の入力完了状況を自動判定して色分け表示（「入力済」＝緑、「未入力」＝赤）し、技能分野の対象外試験セルおよび親項目が「無」の従属セルには自動で `-` を出力します。

## メニュー構成と標準業務フロー (Menu & Workflow)

スプレッドシート上部のカスタムメニューは、日常業務の流れ（時系列）に沿って以下の3つに分類・番号付けされています[cite: 5]。

### 1. メニュー構成
* **`1. 登録者マスタ管理`**[cite: 5]
  * `1. 候補者の新規登録`[cite: 5]
  * `2. 登録者データの修正・更新`[cite: 5]
  * `3. 登録者データの削除`[cite: 5]
* **`2. 案件・採用管理`**[cite: 5]
  * `1. 案件の新規登録`[cite: 5]
  * `2. 簡易リスト作成`[cite: 5]
  * `3. 履歴書作成`[cite: 5]
  * `4. 案件情報の修正・削除`[cite: 5]
  * `5. 面接結果の登録`[cite: 5]
  * `6. 面接結果の修正・更新`[cite: 5]
  * `7. COE申請情報の登録・更新 (COE Info)`[cite: 5]
  * `8. 入国日・入職日の一括登録`[cite: 5]
* **`3. 管理者用（マスタ・同期）`**[cite: 5]
  * `1. 事業者の新規登録`[cite: 5]
  * `2. 採用・未採用リストの同期`[cite: 5]
  * `3. 支払い管理シートへ同期（Funtoco）`[cite: 5]
  * `4. COE infoシートへ同期（Funtoco）`[cite: 5]

### 2. 標準業務フロー（システム利用手順）

| ステップ | 業務タイミング | 操作メニュー | 主な作業内容とシステム処理 |

| **Step 2**<br>案件登録と<br>提案書類作成 | 求人依頼・候補者選定時 | `2. 案件・採用管理`<br>＞ `1. 案件の新規登録`<br>＞ `2. 簡易リスト作成`<br>＞ `3. 履歴書作成` | 1. 受入企業（事業者名）・技能分野・エントリーする候補者IDを指定して案件を作成する（関連ファイルのアップロードも可能）[cite: 5]。<br>※新しい事業者の場合は、先に `3. 管理者用` ＞ `1. 事業者の新規登録` を行う[cite: 5]。<br>2. 受入企業へ提出するための「簡易リスト」および各候補者の「履歴書」を出力する[cite: 5]。 |
| **Step 3**<br>面接日設定 | 面接日程の確定時 | `2. 案件・採用管理`<br>＞ `4. 案件情報の修正・削除` | 対象の案件IDを検索して読み込み、確定した「面接日」を入力し、ステータスを「面接準備」等に更新する[cite: 5]。 |
| **Step 4**<br>面接結果登録 | 面接実施・合否判明時 | `2. 案件・採用管理`<br>＞ `5. 面接結果の登録` | 案件IDを検索し、採用された候補者にチェックを入れて「内定日」を入力し登録する（全員不採用の場合は「採用者なし」にチェック）[cite: 5]。<br>「案件管理」の面接結果詳細が更新され、全候補者のマスタに面接履歴とステータス（採用/未採用）・内定日が自動反映されるとともに、採用者の基本情報が外部シート「COE info」へ自動転記される[cite: 5]。<br>※登録後に結果の変更・辞退・取消が生じた場合は `6. 面接結果の修正・更新` から変更する[cite: 5]。 |

| **Step 6**<br>入国・入職日<br>の一括登録 | 入国・配属スケジュール確定時 | `2. 案件・採用管理`<br>＞ `8. 入国日・入職日の一括登録` | 案件IDで当該案件の採用者一覧を呼び出し、確定した「入国日」「入職日」を一括セット（または個人ごとに微調整）して保存する[cite: 5]。 |
| **Step 7**<br>外部シート同期 | 定期・情報更新後 | `3. 管理者用（マスタ・同期）`<br>＞ `3. 支払い管理シートへ同期`<br>＞ `4. COE infoシートへ同期` | 確定した採用者情報や内定日・入国日・入職日を外部シート「支払い管理」へ同期する[cite: 5]。また、全採用者の最新COE情報を一括で「COE info」へ差分同期する場合は `4. COE infoシートへ同期` を実行する[cite: 5]。 |

## システム構成 (System Structure)

### スプレッドシート（データベース）

* **登録者マスタ**: 全候補者のベースデータ（ID: SD-XXXX）[cite: 5]
* **案件管理**: 求人案件データ（ID: JOB-XXXX）[cite: 5]
* **リスト・出力用**: 未採用者一覧, 採用者一覧, 簡易リスト, 履歴書, 操作マニュアル[cite: 5]
* **各種マスタ**: 事業者マスタ, 送り出し機関マスタ, 日本語学校マスタ, 企業情報, 面談用質問[cite: 5]

### Google Apps Script (バックエンド：全15ファイル)

* `01_共通・メニュー.gs` : シート・列マップ取得の共通関数、UIの制御、カスタムメニュー構築[cite: 5]
* `02_マスタ辞書・事業者管理.gs` : 事業者マスタの重複チェック・新規登録、およびフロントエンド用の各種マスタ辞書生成（候補者辞書・案件辞書・事業者/学校/送り出し機関リスト）[cite: 5]
* `03_候補者管理.gs` : 候補者データの検索（採用案件・技能分野の照合含む）・新規登録・更新・削除処理[cite: 5]
* `04_案件管理.gs` : 案件データの登録・詳細取得・更新・削除・候補者名変更時の連動置換処理[cite: 5]
* `05_ドライブ連携.gs` : Googleドライブ内のファイル/フォルダ検索・案件フォルダ自動作成・アップロード保存・スマートチップ変換処理[cite: 5]
* `06_提案書類作成.gs` : 企業提案用の「簡易リスト」および「履歴書」の自動出力処理[cite: 5]
* `07a_面接結果登録.gs` : 面接対象者の取得、面接結果の新規登録、内定日の設定、面接履歴への自動追記、および採用者の外部「COE info」への初回自動転記[cite: 5]
* `07b_面接結果修正・取消.gs` : 登録済み面接結果の修正・更新（辞退・取消含む）、外部「COE info」の連動更新・削除、および案件削除時のマスタロールバック処理[cite: 5]
* `08a_COE申請情報管理.gs` : COE申請情報（基本情報・英語学歴・分野別試験・パスポート・申請歴・親族情報等）の更新および外部「COE info」への即時同期処理[cite: 5]
* `08b_入国入職日管理.gs` : 案件単位での採用者抽出および入国日・入職日の一括登録処理[cite: 5]
* `09_リスト同期連携.gs` : 「案件管理」を正本（SSoT）とした「登録者マスタ」「採用者一覧」「未採用者一覧」への自動リスト同期処理（`syncListSheets` / `updateCandidateLists`）[cite: 5]
* `10_外部シート連携.gs` : 外部シート「海外ミャンマー管理リスト【Funtoco】」内の「支払い管理」とのデータ同期・一括更新・自動削除処理[cite: 5]
* `11_マニュアル生成.gs` : スプレッドシート内に「操作マニュアル」シートを自動生成・書式設定する保守用スクリプト[cite: 5]
* `12_データ保守・再構築.gs` : 「案件管理」を正本として「登録者マスタ」の面接履歴・ステータス等を一括再構築する保守用スクリプト（`rebuildMasterFromJobSheet`）[cite: 5]
* `13_外部COE連携.gs` : 外部シート「海外ミャンマー管理リスト【Funtoco】」内の「COE info」スマートテーブル（全34列：A列「状況」自動判定・条件付き書式付き）への個別自動転記・全件差分同期処理[cite: 5]
